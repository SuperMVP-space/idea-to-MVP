# AGENTS.md — контракт проекта idea-to-MVP

Единый источник рабочих инструкций. CLAUDE.md только импортирует этот файл.
Профиль: документный репозиторий распространяемого AI-скилла.

## Читать перед работой

1. Последний checkpoint в Discovery/logs/, если он существует.
2. Projects/ROADMAP.md и зарегистрированный план спринта.
3. README.md и docs/quick-start.md.
4. skills/vibecodable-idea/SKILL.md и нужные references.
5. Rulebook/INDEX.md перед действием, для которого есть правило.

## Рабочий цикл

- В чате общаемся по-русски. Таблицы Markdown оформляем как выровненные
  пробелами ASCII-блоки.
- Roadmap → спринт → обязательный план спринта → фичи → спецификация и
  acceptance criteria → работа → проверка → документация и итог спринта.
- План до начала работы содержит зависимости фич и файловые зоны.
  Параллельная работа допустима только без пересечения зон и незакрытых
  зависимостей. Коллизии требуют явного порядка.
- Для документов: spec → критерии → черновик → проверка источников и
  сценариев → current-state документация → append-only итог → roadmap.
  TDD к тексту не имитируем. Код и скрипты проходят полный TDD.
- Не объявлять результат готовым без свежего evidence. При изменении скилла
  проверять пользовательское поведение, а не только заголовки и формулировки.
- Фактические утверждения для учеников проходят два независимых аудита.

## Скиллы и проверки

- Неоднозначный дизайн: кастомный brainstorming, не superpowers:brainstorming.
- Содержательная работа: spec-driven-development; новый/изменённый скилл:
  skill-creator. Перед завершением: verification-before-completion.
- Bootstrap/аудит контура: standardize-supermvp-project.
- Если обязательного скилла нет, назвать пробел и применить контракт вручную.
- Install/lint/typecheck/build не применяются: исполняемого продукта и
  зависимостей нет. Проверки: validator skill-creator, разрешение ссылок,
  целостность выдаваемых файлов, сценарные ответы агента и вычитка по spec.
  Путь к validator зависит от установки; на Windows запускать Python с
  `-X utf8`. Не обещать GUI-пилот по структурной проверке.
- Аудит контура: `python -X utf8 <standardize-supermvp-project>/scripts/audit_project.py . --profile document`.

## Границы и сохранение

- Не коммитить и не пушить без разрешения владельца для текущей задачи.
- Не удалять логи, ветки, worktree или другие рабочие артефакты без разрешения.
- Не включать секреты, персональные данные и внутренние материалы курса.
- Скилл поддерживает личный, полностью бесплатный и коммерческий проект.
  Монетизация не обязательна; расчёт заработка относится к такому намерению.
  Карточка и исследование не доказывают PMF, продажи или полезность.
- Изменение поведения начинается в skills/. Inline-адаптер в docs/ должен
  сохранять тот же смысл и все необходимые справки.
- Все evidence и временные результаты — внутри предназначенного вложенного
  каталога этого проекта, без системного TEMP и внешней памяти.
- В корне поддерживаем существующие README.md, AGENTS.md, CLAUDE.md и
  .gitignore и .gitattributes. Новые корневые файлы — только решением владельца.
- Логи Discovery/logs/ append-only; новые выводы не стирают прежние ошибки.
  Новые правила проходят через Rulebook/INDEX.md с ссылкой на основание.

## Gate завершения

Критерии подтверждены, источники проверены, README/docs актуальны, итог
спринта записан, новые правила зарегистрированы, roadmap отражает статус.
Полное состояние сохранять в проекте; checkpoint имеет один входной файл.
